# Qwen3.8-Flash-Next と Qwen3.8-27B の API 比較 (2026-11-08)

## 1. 目的

RAM の増設・CPU の交換・2 枚目の GPU の追加をして Qwen3.8-Flash-Next (125B MoE) を手元で 3〜4bit で動かす価値があるかを判断するため、圧縮していない Flash-Next を今の Qwen3.8-27B と同じ課題で比べた。

公開ベンチマークでは Flash-Next が上である (Artificial Analysis の Terminal-Bench 4.0 で 25.3% 対 5.6% など)。うちの使い方 (アラート調査・techfeed・シンプルなエージェント) でも同じ差が出るかを確かめる。

## 2. 条件

| 項目 | 内容 |
| :-- | :-- |
| 実施日 | 2026-11-08 |
| API | OpenRouter |
| Flash-Next | `qwen/qwen3.8-flash` (Hugging Face 上の元モデルは `Qwen/Qwen3.8-Flash-Next`)。配信は Alibaba |
| 27B | `qwen/qwen3.8-27b`。配信は ModelRun |
| 生成の設定 | temperature 0.6、max_tokens 16000、思考は既定 (有効) |
| エージェントのツール | `list_dir`・`grep`・`read_file` の 3 つ。読めるのは git で管理しているファイルだけで、secret・sops・kubeconfig・.env を名前に含むものとこのディレクトリは除く |
| エージェントの手順の上限 | 15 (A3 の Flash-Next の 2 回目だけ 25) |

OpenRouter の Flash-Next は文脈長が 100 万トークンで、公開されている重み (26 万トークン) と全く同じかは分からない。

## 3. 課題

| ID | 種類 | 内容 | 回数 |
| :-- | :-- | :-- | :-- |
| A1 | リポジトリ調査 | egress-gateway と pg-cluster-2 の nixos-upgrade がいつ走るか、どこで決まるか、起動直後にも走るか | 各 1 |
| A2 | リポジトリ調査 | LiteLLM の `auto` が lm-server の停止時にどこへ切り替わるか、再試行とタイムアウト | 各 1 |
| A3 | リポジトリ調査 | lm-server の llama.cpp を Claude Code から使うための工夫を 3 つ以上 | 各 1 (Flash-Next は追加で 1) |
| L1 | ログ読解 | k8s の CrashLoopBackOff。DNS の警告などのおとりを混ぜ、原因は Secret の同期後のパスワード不一致 | 各 1 |
| L2 | ログ読解 | nixos-upgrade の評価エラー。ほかのホストへの影響と直し方 | 各 1 |
| J1 | JSON 出力 | techfeed と同じ形の選別と台本。件数・文字数・話者の順番などを機械で検証する | 各 3 |
| E1 | 差分出力 | `nix/hosts/lm-server/llama-cpp.nix` の値とコメントを書き換える unified diff。`patch` で当たるかを機械で検証する | 各 2 |

L1・L2 のログは、この比較のために作ったものである。課題の本文は `scripts/tasks.py` にある。

## 4. 結果

| 課題 | Flash-Next | 27B | 差 |
| :-- | :-- | :-- | :-- |
| A1 | 正解。存在しないツール `read_path` を 1 回呼んだ。11 手順 | 正解。「daily が 00:00 になるのは systemd の解釈で、リポジトリには書かれていない」と根拠の範囲を区別した。11 手順 | 同等 |
| A2 | 正解。「タイムアウトで落ちるときは 600 秒待ってから切り替わる」と指摘した。7 手順 | 正解。3 手順 | Flash-Next がやや上 |
| A3 | 1 回目は 15 手順を使い切り、回答なし。2 回目 (上限 25) は 13 手順で 6 項目を挙げたが、`request_timeout 600` を Claude Code 向けの工夫に数えるなど言い過ぎが混ざった | 4 手順で 6 項目を正確に挙げた | 27B が上 |
| L1 | パスワード不一致を当て、Argo CD による Secret の同期と、古い Pod が起動時の値を持ち続けていることを結びつけた | パスワード不一致は当てた。Secret の同期には触れず、直し方に `kubectl` による直接書き換えを挙げた (GitOps に反する) | Flash-Next が上 |
| L2 | 正解 | 正解 | 同等 |
| J1 | 3 回とも制約を満たした。台本に記事に無い話 (KubeSpan と LXC の相性など) が少し混ざった | 3 回とも制約を満たした。ローカル LLM の運用者向けに llama.cpp の記事を毎回選んだ | 同等 |
| E1 | 2 回とも当たった。書き換えたコメントにも矛盾が無かった | 2 回とも当たった。2 回とも、確かめていない「32K なら収まることを確認済み」をコメントに書いた | Flash-Next がやや上 |

### 4.1 トークンと費用

| モデル | 実行回数 | 出力トークン (うち思考) | 費用 |
| :-- | :-- | :-- | :-- |
| Flash-Next | 11 | 72,653 (61,735) | $0.053 |
| 27B | 10 | 53,040 (46,275) | $0.142 |

- A3 の追加の 1 回を除いても、Flash-Next の出力は 27B の約 1.2 倍である。A1 だけは 27B の方が多かった。
- エージェントの課題では、Flash-Next の方が広く調べる (A2 は 7 手順対 3 手順、A3 は 13〜15 手順対 4 手順)。
- 経過時間は配信側のハードで決まるので、比較には使わない。手元で動かした場合の見積もりは、A3 で 27B が約 2 分 (2.2k トークン ÷ 22 tok/s)、Flash-Next が約 7 分 (7.8k トークン ÷ 20 tok/s) になる。

### 4.2 思考ループ

どちらのモデルでも、思考が止まらなくなる例や、出力が上限で打ち切られる例は無かった。2bit (IQ2_XS) で起きたループ ([../README.md](../README.md) 3.2) は、圧縮が原因だった可能性が高い。ただし、Claude Code の長いシステムプロンプトでは試していない。

## 5. 結論

うちの使い方に近い課題では、圧縮していない Flash-Next でも 27B との差は小さかった。原因を深く読む課題 (L1・A2) では Flash-Next が上で、エージェントの手数の少なさ (A3) では 27B が上だった。

手元で動かす場合は 3〜4bit に縮めることになり、精度はこの結果を下回る。生成速度も、CPU・RAM・GPU をすべてそろえて約 20〜35 tok/s、そろわなければ 27B の 22 tok/s 以下という見積もりである。今の用途では、ハードに投資して 27B を置き換える価値は薄く、27B を続ける。

## 6. 注意点

- 回数は各 1〜3 回で、文章の回答の良し悪しは人の目で判定した。
- 1 回目の一括実行では、配信側の応答が 600 秒止まって 2 件 (27B の A1、Flash-Next の E1 の 2 回目) が失敗した。この 2 件は結果から除き、走らせ直したものを載せている。走らせ直しでも、27B の E1 の 2 回目と J1 の 2 回目で応答が止まり、自動で 1 回再試行した。
- A3 の 2 回目以外は、ツールの呼び出しの記録を残していない。

## 7. ファイル

| パス | 内容 |
| :-- | :-- |
| `results.jsonl` | 生の結果。1 行が 1 回の実行で、回答・usage・経過時間・機械検証の結果を含む |
| `answers.md` | `results.jsonl` の回答を課題ごとに並べたもの |
| `scripts/tasks.py` | 課題の本文と、L1・L2 のログ、J1 の候補記事 |
| `scripts/agent.py` | ツール付きエージェントのループ |
| `scripts/run_all.py` | 課題を並列に走らせ、`results-<日時>.jsonl` に書き出す |
| `scripts/orc.py` | OpenRouter の呼び出し |

## 8. 再実行の手順

OpenRouter の API キーを環境変数 `API_KEY` に入れるか、リポジトリルートの `.env` (git 管理外) に `API_KEY=` で書く。

```bash
python3 -I docs/ideas/strata/api-comparison/scripts/run_all.py \
  agent,qwen/qwen3.8-flash,A1,1 \
  single,qwen/qwen3.8-27b,J1,1
```

引数は `種類,モデル,課題,回数目` である。種類は、A1〜A3 なら `agent`、それ以外なら `single` にする。
